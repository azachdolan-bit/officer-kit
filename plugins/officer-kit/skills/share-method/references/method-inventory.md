# Method inventory

Before a builder is written, sort everything the product carries into three bins. Only the first goes in the builder.

## 1. Method (keep)

The author's own engineering, which works on any source of the same kind:

- the product's form: file type, sections, layout, pacing, scoring, levels of difficulty
- how the source is read: capture, transcription, read back, what to do with an unreadable line
- how facts are extracted: the categories, taken exhaustively
- how the product is verified: re-deriving worked examples, a self test, a count reported
- interaction rules: who speaks, turn length, when the coach talks, how errors are corrected
- how invented values are constrained so they never contradict the source (build geometry backwards, avoid boundary values unless the boundary is the lesson)
- delivery: what the message names, and that gaps are named rather than filled

## 2. Content (strip)

Anything the source or the product says about the subject:

- terms, acronyms, code and model numbers, names of units, places, people, and publications
- values: distances, times, quantities, thresholds, frequencies, percentages
- lists, sequences, formats, option sets, and their order
- worked examples, sample answers, questions, and distractors
- the wording of any sentence from the source

## 3. Emphasis (convert, then keep)

What the author learned while studying: the traps, the tricky rule, the line everyone misses. Emphasis is not a term or a value, so a leak scan cannot see it, but it still passes on the author's study. Convert each item into the exhaustive category it belongs to, so the builder finds it and everything like it without being told where to look.

| Emphasis in the product | Category in the builder |
|---|---|
| "watch the rounding rule on line 4" | every stated convention for numbers, including any tie rule, verbatim |
| "the card's option list has a fifth option most people forget" | every option set, complete, with the criteria for each |
| "remember you send nothing below the threshold" | every threshold, and any case where the right action is to do nothing |
| "this step comes before that one, unlike the book" | structure and order exactly as printed; never normalize toward the familiar version |

When an item will not convert because it only makes sense for one subject, it stays out.

## Subject posture

A builder that works on any handout of its kind is self-evidently a method. A lightly subject flavored builder (a report drill, a radio simulator) is acceptable when it still names nothing from the subject; say which posture the builder takes in the reply.
