# Formats

Pick the format the user named. Ask only when the request fits two. Every format is built from the spec and passes the gates first.

## Study guide (`guide`, .docx), the default

Order: title, how to use, **skeleton**, objectives, **knowledge sections** in source order, **practice scenarios** with the key on its own page, **practice quiz** with the key on its own page, flashcards if asked.

- Knowledge first. Concepts, definitions, sequences, and numbers in prose and tables, verbatim where the source is verbatim and testable. No grading sheets, point values, or rubric step numbers up front; a sequence the rubric grades is still knowledge and stays, without the rubric framing.
- Scenarios only where applied judgment is graded (planning, procedures with decisions, calculations). The situation is invented; every fact and number inside it comes from the source, and every number is verified in code before the guide ships. Pure recall material gets knowledge and quiz only.
- Where the source is an issued document (a slide, a card, a form), reproduce what it contains rather than describing it.

## Interactive walkthrough (`walkthrough`, one .html file)

A replacement for reading the lesson, not a summary of it. A map section first (the lesson as branches, with recall modes that hide details or everything), then one section per chapter: the teaching body, the complete source text for that chapter behind "Read it as issued", and a check whose every answer is in that section's own text. A final check mixes every section.

## Condensed handout (`handout`, .docx)

For a user who wants to take their own notes. Medium density: a sentence or two per concept so it reads alone. Keep every list, definition, formula, and worked example verbatim. Redraw flow charts as step boxes. Drop organization wire diagrams and blank forms, but say what each form is for and name its headings. Flag any internal error in the source with both the source's wording and the corrected figure. No quiz, no flashcards. Gate 1 runs as a report here, not a pass line: read every sentence it lists as missing and confirm each is context rather than a list, definition, formula, or worked example.

## Whiteboard session (`whiteboard`, .docx)

For a group at a board. Per topic, in this order: **WRITE** (the material laid out to transcribe: acronym spine tables, numbered sequences, comparison tables, short lines, no paragraphs to summarize on the fly), **TALK** (callouts where discussion belongs: TRAP, DISCRIMINATOR, MEMORY HOOK), then **BOARD PLAY** (ERASE what to wipe, REBUILD what they reconstruct cold, COLD CALL eight to thirteen questions with answers in parentheses, IF THEY MISS ONE THING the must say line). Order topics by the priority the user gives, tag objective codes inline, and put a coverage index at the back. Suggest a numbers box kept in a corner of the board, and timings per topic.

## Quiz me (chat, no file)

One question at a time. Wait for the answer, grade it in one line with the source's reason, then send the next question. Never paste the set first and never reprint a question. At the end, list what was missed and offer to drill those. The quiz rules below still apply.
